# AGENTS.md

## 1. PROJECT
Redaktix (`package.json` name `redaktix`, app root `privacylab/`) is a browser-based, local-first tool that detects and redacts PII and developer secrets in screenshots. Top priority is RECALL: never miss sensitive data. A false positive is cheaper than a false negative.

## 2. PIPELINE
- OCR: `src/js/ocr.js` `initializeOcrWorker` then `recognizeScreenshot` → `recognizeWithWorker`. Pass 1 is `worker.recognize` on the raw canvas. Pass 2 uses `src/js/ocr-adaptive.js` (`discoverSuspiciousRois`, `cropRgba`, `upscaleGray`, `adaptiveThresholdGray`) and recognizes that ROI only.
- Merge: `ocr.js` `mergeDistinctWords`; `src/js/sensitive-detectors.js` `mergeGroupedOcrWords`, `mergeIpv6OcrWords`, `getMatchBoundingBoxes`; `ocr-adaptive.js` `mergeSpatialCandidates` and `sameTcknGlyph`.
- Detect: `src/js/editor.js` `buildDetectionsFromOcr` → `src/js/structured-lines.js` `detectStructuredDataFromLines` plus extractors in `sensitive-detectors.js` (TCKN, VKN, cards, IBAN, tokens, email, phone, IPv4/IPv6, PEM/`private_key`, `bearer_token`, `connection_url`, `env_secret`, `passport`, `seed_phrase`). Cross-line joins use `src/js/cross-line.js` `buildCrossLineWindows` (Bearer, IBAN wrap, seed phrase).
- Mode: single editor mode `global-turkey` (`DEFAULT_DETECTION_PROFILE`). Profile UI/storage writes removed; `readStoredDetectionProfile` ignores legacy keys safely. `filterDetectionsForProfile` / `isDetectorEnabled` / `limitToToolDetectors` never drop `ALWAYS_ON_DETECTORS`.
- Suppress: `src/js/detection-suppression.js` `suppressShadowedDetections` (strong types including ALWAYS_ON are not dropped as shadows).
- Draw: `editor.js` `paintEditorSurfaces` (blackout `fillRect`, `drawBlurRedaction`, `drawPixelateRedaction`). Export: `src/js/export-clean.js` `createCleanOutputCanvas` → `canvasToBlob` (fresh canvas; strips EXIF/XMP). Batch boxes: `src/js/app.js` `blackoutDetections`.
- Tesseract: `tesseract.js` `createWorker` in `ocr.js`. `workerPath`, `corePath`, and `langPath` are same-origin `{BASE_URL}assets/ocr` (`public/assets/ocr`). Languages `eng`+`tur`. One worker. `public/sw.js` / stamped `dist/sw.js` precache OCR core, lang, and worker for offline editor use.
- Runtime network: OCR assets are same-origin fetches; the screenshot is not uploaded. This is not zero-network. No Google Analytics/Tag Manager. `public/sw.js` fetches same-origin GETs. `editor.js` `openDeviceImagePicker` fetches a device photo URI.

## 3. DETECTION RULES
### ALWAYS_ON (`detection-profiles.js` `ALWAYS_ON_DETECTORS`)
Always enabled, including on tool pages via `limitToToolDetectors`:
`tckn`, `vkn`, `credit_card`, `iban`, `private_key`, `bearer_token`, `connection_url`, `env_secret`, `passport`, `seed_phrase`.

Scan note (TR/EN i18n `editor.scanAlwaysOnNote`): cards, IBAN, TCKN, VKN, API keys and private keys are always scanned.

### Checksums / validation
- **IBAN**: `isValidIban` / `ibanMod97` in `sensitive-detectors.js` (country length table + mod-97). OCR country-code repair and cross-line wrap supported. Built-in custom rule `iban` / `TURKISH_IBAN_PATTERN` still contributes pattern matches.
- **TCKN**: `isValidTckn` — strict 11-digit checksum; auto-redact only when valid (review path for failures/repairs per detector policy).
- **VKN**: `isValidVkn` — 10-digit Turkish tax-id checksum; unlabeled / checksum-fail cases stay review-oriented per `buildDetectionReview`.
- **Cards**: Luhn via `passesLuhn` / `detectCreditCard`.

### Other detectors (single-mode set)
Also active in single mode: `api_token`, `email`, `ipv4`, `ipv6`, `phone`, `person_name`, `location`, `session_id`, `custom_rule`.

### Newer secret detectors
- `private_key`: PEM `BEGIN … PRIVATE KEY` (+ loosened OCR / high-entropy body fallback).
- `bearer_token`: `Bearer` + token; cross-line via `buildCrossLineWindows`.
- `connection_url`: credentialed DB/URL forms (Redis, Postgres, etc.); whitespace-tolerant host/port join.
- `env_secret`: `.env`-style `KEY=value` secrets (short values → review).
- `passport`: labeled passport / pasaport numbers (unlabeled → review).
- `seed_phrase`: 12/24 BIP39-like word runs; cross-line via `buildCrossLineWindows`.

`detectionsForAutomaticRedaction` skips `needsReview` items.

## 4. FILES TO IGNORE
Never edit by hand: anything under `android/**` (including generated `android/**/assets/public`), and `dist/` (generated by `npm run build`).

- `tests/iban-valid.test.js`, `tests/iban-policy.test.js`, `tests/iban-*-*.test.js` — IBAN mod-97 / OCR / E2E.

Hard test rule: do not import `ocr.js` / `loadOcrModule()` from unit tests. Do not auto-scan on profile change (profile menu removed).

## 6. BUILD
`npm run build` → `vite build && node scripts/build-tools.js` (stamps `dist/sw.js` PRECACHE + BUILD_HASH). Then sync Android when needed: `npx cap sync android`. `capacitor.config.json` `webDir` is `dist`. Never hand-edit `dist/` or `android/**/assets/public`.

## 7. HARD RULES
- Never loosen or remove a checksum validation (IBAN mod-97, TCKN, VKN, Luhn).
- Never drop an ALWAYS_ON detector from tool pages or suppression.
- Never add network requests, telemetry, or external CDNs.
- Never delete or weaken a test to make it pass.
- Do not modify files outside the task scope.
- Do not touch `android/**` unless the task explicitly requires it.
- Every bug fix must come with a failing test first, then the fix.
- Run `node --test` / the full suite after changes. In CI (`CI=1`), `dist/` must exist for privacy/build scans.
- Do not invent product features; match existing code and detectors.

## KNOWN ISSUES
- App id is `com.redaktix.app` (`MainActivity.java`, `applicationId`). Android unit and instrumented tests may still use `package com.getcapacitor.myapp`.
- Review-only paths remain for unlabeled VKN/passport, short env secrets, seed phrases, and some IBAN OCR repairs without checksum+label.
